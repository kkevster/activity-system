# 03-config.md
## 配置管理方案

### 1. 配置管理计划
本项目采用 Git 作为版本控制工具，配置管理计划如下：
- **版本控制工具**：Git
- **代码托管平台**：GitHub
- **主分支**：`main` 分支，用于存放稳定、可发布的代码。
- **开发分支**：`dev` 分支，用于日常开发和功能集成。

### 2. 分支策略
- **main 分支**：受保护分支，仅允许通过 Pull Request (PR) 合并代码，禁止直接推送。
- **dev 分支**：作为集成分支，所有功能开发完成后，需合并至 dev 分支进行测试。
- **feature 分支**：针对具体功能（如“登录功能”）创建的临时分支，开发完成后合并回 dev。

### 3. 权限管理
- **管理员 (Admin)**：拥有仓库所有权限，负责合并 PR 至 main 分支。
- **开发者 (Developer)**：拥有 push 权限，可创建 feature 分支并提交代码。
- **观察者 (Observer)**：仅有读取权限，用于查看代码历史。

### 4. 提交规范
- **Commit Message 格式**：`类型(范围): 描述`
  - 例如：`feat(login): 添加用户登录接口`
  - 例如：`fix(ui): 修复按钮点击无反应 bug`
- **提交频率**：每日至少提交一次，确保代码不丢失。
