5. 冲突产生原因与解决过程
这是本次实验的技术核心点：
1. 冲突产生：成员 `xieyufei` 在 GitHub 远程端修改了 `docs/conflict.md` 提出了“扫码枪方案”；与此同时，成员 `huangwenchen` 在本地分支修改了同一位置，提出了“手机动态二维码方案”。
2. 冲突识别：当 `huangwenchen` 执行 `git pull origin main` 时，Git 报出内容合并冲突。
3. 手工处理：`huangwenchen` 利用 VS Code 冲突编辑器，分析了两份方案的优劣，最终决定采用“保留双方更改”的策略，将两人的技术见解整合为一个更完备的签到系统说明。

收获：掌握了 Git 解决冲突的完整闭环，深刻理解了“交付物导向”在 WBS 编写中的重要性。
